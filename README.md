# cc-clinic-lab · 临床试验访视采集台

数据工程产品线基线。题号前缀 `clinic-*`，默认端口 **7600**。

## 技术栈

- 后端：CherryPy + SQLite
- 前端：原生 JS SPA（顶栏薄荷绿丝带导航）
- 会话：itsdangerous 签名 Cookie
- 测试：pytest + httpx（依赖已列入 requirements）

## 登录

- 地址：`http://127.0.0.1:7600/login`
- 账号：`admin` / `123456`

## 页面

| 页面 | 能力 |
|------|------|
| 试验中心 | 中心登记、启停/观察、配额、方案版本生效 |
| 访视批次 | 开批、模拟抓取、追加访视行、合格入库、收齐/关闭 |
| 字段质控 | 按批/全量扫描、发现关闭/重开 |
| 缺口补采 | 排队、执行成功/失败、失败重试 |
| 访视对账 | 缺口/发现/补采对照、中心矩阵、审计 |
| 台参数 | 设置读写 |

## 主链

中心 → 访视批次抓取 → 质控发现 → 缺口补采 → 对账报告；设置与审计贯穿写操作。

## 本地

```powershell

```

## 审计归档钉定（clinic-bug-15，甲路·旁路账册）

修复「参数页归档徽标亮着、读轨却停在旧归档键号」的假绿：

- **徽标如实**：未收口时徽标显示「活审计可改」，皮面半修只亮展示键、不换读轨，系统判定为假绿。
- **闸口挡活审计改写**：徽标与读轨键号对不上时，质控扫描/关闭重开、补采排队/执行/重试、对账、抓取/入库、台参数、中心/方案等所有写审计的入口统一返回 409，库内无变化。初始如实态与收口对齐态正常放行。
- **甲路单收口（禁双开）**：收口在单事务内把当刻 `audit_events` 逐行封进只追加旁路账册 `meta.audit_arch_book_*`，锁定全量指纹、置 `reject_refresh=1`、读轨分叉到 `cutover_book`；提交即入库，失败整体回滚并报「入库失败」。乙路双写入口一律 409，不写任何状态。
- **拒回刷**：收口后新增的活审计事件不进账册、指纹不变。
- **缺锁争用**：`audit_arch_sealed` 唯一键 INSERT 抢锁，重复/并发收口只有一份成功。
- 读接口（dashboard/snapshot/board 等）纯读无副作用；前端六个页面的归档徽标均取业务库真实状态，假绿显红牌。
- 验收：`pytest`（含 `tests/test_audit_arch_gate.py` 败测回归）全绿，并以真实运行的页面/接口核对业务库为准。
